# DolphinClient 0.110.0 — The admin portal finally sees accounts

Target: `deploy/admin-stats.mjs` and the website's `/admin` overview. This
release does not touch the client or launcher.

## Changes

- **`admin-stats.mjs` now reads the account database.** It already reads the
  nginx logs, the download manifest and the changelog to build one
  `stats.json`; it now opens `account-api.mjs`'s own SQLite file too —
  read-only, same default path and `ACCOUNT_DB` override the account API
  itself uses — and adds counts to that same file: total accounts, how many
  are email-verified, how many have a linked Minecraft profile, and how many
  sessions are currently active (not expired). Signups per day are folded
  into the same per-day series the traffic charts already use, so a new
  "New accounts" chart is just another `<Bars>` call, not a new component.
  Only counts and dates are read out — no email address or password hash
  ever leaves that database or appears in `stats.json`.
- **The admin page shows it.** A new "Accounts" stat tile sits next to the
  existing Live version / Downloads / Update checks / Visitors tiles, and a
  "New accounts" bar chart sits in the "Last 30 days" row next to page
  views, visitors, downloads and update checks.
- **Graceful when there's no account database.** A server that never ran
  `setup-account-api.sh` (or one where the account service hasn't started
  once yet) gets `accounts: null` in `stats.json` — the tile shows "—" and
  the chart's bars are simply zero, matching how every other section of this
  page already handles a missing data source rather than erroring the whole
  build.
- **Tests.** New `deploy/test-admin-stats.mjs` runs the real script as a
  subprocess against a throwaway webroot, log directory and account
  database, and checks the counts it produces — including that an expired
  session is excluded and that a missing database degrades to `null` rather
  than crashing the script.

## Reference

No new environment variables beyond `ACCOUNT_DB`, which already existed as
`account-api.mjs`'s own database-path override and is simply read a second
time, read-only, by this script. No deployment script changes were
needed — the existing `dolphinclient-admin-stats.timer` already runs this
script as root, which already has filesystem access to
`/var/lib/dolphinclient/account-api/account.db`.
