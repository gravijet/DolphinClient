# DolphinClient 0.111.0 — Admin account management is here

Target: `admin-api.mjs`, account database schema, and the website's new `/admin/accounts` page. This
release does not touch the client or launcher.

## Changes

- **New admin accounts page.** `/admin/accounts` is a search-and-manage dashboard for accounts.
  Admins search by email or display name, see when each account was created and last logged in,
  and can ban/unban or permanently delete accounts. Pagination built in (50 per page, next/previous
  buttons). Shows account status at a glance — active or banned.

- **Account ban functionality.** The users table gets a new optional `banned_at` column; when set to
  a timestamp, that account cannot sign in (login endpoint returns HTTP 403 with "this account has
  been banned"). Banned accounts are never deleted automatically — they stay searchable and admins
  can unban them if needed. Existing deployments: the column is added automatically on the next
  account-api startup if missing.

- **Admin API extended.** `admin-api.mjs` now also manages accounts:
  - `GET /accounts?q=email&limit=50&offset=0` — paginated account list, optionally filtered by
    search query.
  - `PATCH /accounts/<id>` with `{banned: true|false}` — ban or unban an account.
  - `DELETE /accounts/<id>` — permanently delete an account (cascades to all sessions and password
    resets for that user).
  - All require Cloudflare Access auth (same gate as the rest of the admin portal).
  - Graceful 503 if the account database doesn't exist yet (a server that hasn't run account-api
    or has no ACCOUNT_DB configured).

- **Account login enforcement.** `/auth/login` now checks if the account is banned before
  accepting the password; if `banned_at IS NOT NULL`, the endpoint returns 403 instead of 200.

## Reference

No new environment variables. Existing deployments that set `ACCOUNT_DB` will have account
management automatically available on the admin portal. A server with no account database or no
account-api configured yet gets a graceful "not set up" message instead of crashing.

### Database migration

Existing SQLite databases from before this release automatically get the `banned_at` column on the
next server startup (in-place, no manual migration step). All existing accounts default to
`banned_at = NULL` (unbanned).

### Deployment

No changes to deployment scripts or systemd units. The existing `dolphinclient-admin-api.service`
gets the new endpoints immediately; no rebuild or restart is needed once the code is in place.
